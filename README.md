# Лабораторна робота №9
## Тема: Паралельність, багатопроцесність та оптимізація
# Мета
Ознайомитися з основними підходами до паралельного та конкурентного виконання програм у Python, дослідити вплив Global Interpreter Lock (GIL) на виконання CPU-bound та I/O-bound задач, навчитися використовувати threading, multiprocessing, ThreadPoolExecutor і ProcessPoolExecutor. Навчитися виявляти вузькі місця (bottlenecks) у Python-програмах за допомогою timeit, cProfile і tracemalloc, аналізувати час виконання та використання пам'яті, застосовувати NumPy для векторизації обчислень і caching для уникнення повторних дорогих операцій.

## Опис алгоритму (Варіант №3)
Проєкт реалізує експериментальне дослідження продуктивності, паралельності та оптимізації для каталогу інтернет-магазину (Варіант 3) обсягом 100 000+ товарів:
1. **Предметна область**:
   - Датаклас `Product` (назва, категорія, ціна, кількість, загальна вартість).
   - Базові функції управління залишками: `calculate_inventory_value()`, `find_product()`, `filter_by_category()`, `find_most_expensive()`.
2. **Профілювання та пошук Bottlenecks**:
   - Застосовано стандартний інструмент `cProfile` для аналізу накопиченого часу (`cumtime`) та кількості викликів (`ncalls`).
   - Використано модуль `tracemalloc` для вимірювання пікового використання оперативної пам'яті (`peak memory`).
3. **Порівняння реалізацій та векторизація (NumPy)**:
   - Порівняно базовий розрахунок статистики товарів на циклах Python (`statistics_python`) проти векторизованого підходу `statistics_numpy`.
   - Векторизація NumPy забезпечила прискорення (speedup) у 1.8 рази зі зменшенням навантаження на інтерпретатор.
4. **Паралельні обчислення (CPU-bound та GIL)**:
   - Досліджено виконання важкої CPU-bound задачі динамічного ціноутворення на послідовному виконанні, `ThreadPoolExecutor` та `ProcessPoolExecutor`.
   - Експериментально підтверджено вплив GIL: використання потоків для чисто CPU-bound задач не дає прискорення через оверхед контекстних перемикань.
5. **Синхронізація потоків та Race Condition**:
   - Змодельовано конкурентне списання залишків товару у пам'яті (`InventoryStock`) 10 потоками по 100 операцій.
   - Продемонстровано стан гонитви (race condition) без блокувань та його повне усунення за допомогою `threading.Lock`.
6. **Кешування та Cache Invalidation**:
   - Застосовано `@lru_cache` для дорогої статистики категорій товарів.
   - Продемонстровано прискорення повторних викликів (speedup понад 30x) та реалізовано версійну інвалідацію кешу (`invalidate_category_cache`).
7. **Автоматизоване тестування**:
   - Набір із 11 автоматизованих тестів через `pytest` із покриттям 90.72%.

## Висновок
У ході лабораторної роботи №9 було досліджено різницю між concurrency та parallelism у Python, вивчено дію механізму GIL у CPython, проведено профілювання за допомогою cProfile та tracemalloc. Експериментально доведено високу ефективність векторизації через NumPy та кешування результатів через lru_cache, а також коректно реалізовано захист від стану гонитви за допомогою Lock.
